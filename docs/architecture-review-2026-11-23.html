Problem. Only `state.rs` sets a bad file aside; a corrupt or wrong-version route, track or waypoint file is an `Err` into `?` in `Plotter::new`, so the chart never appears. Waypoints bypass `geo_data` with their own unversioned, unvalidated format. Track's path is a parameter passed from two sources of truth.

Solution. A `GeoFile` module owning path, format version, validation, migration, set-aside and atomic write; each collection owns one and every save goes through it.

  • locality: file policy in one module
  • non-negotiable restored for all four files
  • interface shrinks: load, save
  • tests: corrupt route/track/waypoints set aside
  • delete two save paths, one format

Problem. `screen_to_gps` wants "centre minus click", so every caller computes it from `Screen`'s public width; the result is never wrapped or range-checked, so a click past the antimeridian stores a longitude above 180 that `geo_data::write` then rejects on every save.   • tests need no SQLite fixture
  • renderer trims five internal-only pub fns

Problem. Gesture state is scattered over seven `Plotter` fields and the mode `match` is repeated four times, with no seam a test can reach.   • locality: gesture bugs in one module
  • tests: 500 ms long press, tolerance, grab lock
  • one zoom semantics via AppAction
  • seven Plotter fields become one

Solution. Do not unify the types. Share the helpers (candidates 1, 2, 5) and keep four modules with four different shapes. A common type would be forced and would fail the deletion test.

Pass the deletion test — leave alone

  • geo_data: small and deep; extend it (candidate 1), do not split it
  • Confirmation/ConfirmDialog, MenuBar/Topbar: the font-free halves are the test seam; the pass-throughs buy SDL isolation
  • ClipRect, clip_segment, gps, projection: pure and deep
  • Streamer: three methods hide three threads and frame dropping
  • apply_delta, update_ais_target, retain_fresh: good seams
  • MBTilesRenderer core (look_at, set_rotation, render_frame, prefetch_step, zoom): deep; trim the five internal-only pub fns, do not break it up
  • Route::active_waypoint: the model clamp

Smaller friction noted, not carded: all Session fields pub (resolves with 3 and 6); display_buttombar is pure text composition that could be Session::status_line(); Buttombar re-implements screen::draw_text twice and unwraps on the render thread; CLAUDE.md says Plotter::sync_view where it is now Session::sync_view; drag_map presents without overlays, so boat, route and AIS vanish while panning.

Top recommendation

1. One persisted-collection module

It is the only candidate that fixes a broken non-negotiable: today a corrupt route, track or waypoint file keeps the chart off the screen. It is self-contained, three tests go red first, and it lays the path and format foundation that candidates 5 and 6 build on. Candidate 2 (ChartView) is the next most valuable and the natural second step, since 3 and 7 both want it.
